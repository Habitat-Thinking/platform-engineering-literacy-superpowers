### Stack

- **Primary languages**: Markdown (content-only project — no executable code)
- **Build system**: None
- **Test framework**: None
- **Container strategy**: None
- **Plugin system**: Claude Code plugin (`plugin.json` manifest, `SKILL.md` files)
- **Linter**: markdownlint-cli2 (configured via `.markdownlint.json`)
- **CI**: GitHub Actions (`lint-markdown.yml`)

### Conventions

<!-- Describe how content should be written here. Each convention should be
     concrete enough that a reviewer could objectively say whether content
     follows it or not. -->

- **Naming**: Directories use lowercase kebab-case. Skill files are named `SKILL.md` inside a directory matching the skill name. YAML frontmatter must include `name` and `description` fields.
- **File structure**: Multi-plugin layout — each plugin lives in its own top-level subdirectory with a `.claude-plugin/plugin.json` manifest. Skills live in `skills/<skill-name>/SKILL.md` with an optional `references/` subdirectory for supporting material.
- **Content integrity**: Internal references between skills and reference files must resolve to existing files. YAML frontmatter on all skill files must be present and well-formed (valid YAML with required `name` and `description` fields).
- **Documentation**: Content voice is authoritative but accessible, written for practising platform engineers. CHANGELOG must be updated in every PR. README must be updated in every PR when user-facing changes are made. Markdown must pass linting locally and in CI.

## Constraints

<!-- Each constraint becomes a verification slot — backed by either a

### Markdown lint passes

- **Rule**: All Markdown files must pass markdownlint-cli2 with the project's `.markdownlint.json` configuration
- **Enforcement**: deterministic
- **Tool**: markdownlint-cli2 "**/*.md"
- **Scope**: pr

### No secrets in source

- **Rule**: No API keys, tokens, passwords, or private keys may appear in committed source files
- **Enforcement**: deterministic
- **Tool**: gitleaks detect --source . --no-banner --exit-code 1
- **Scope**: pr

### YAML frontmatter valid on skill files

- **Rule**: Every `SKILL.md` file must have valid YAML frontmatter containing at minimum `name` and `description` fields
- **Enforcement**: agent
- **Tool**: agent review
- **Scope**: pr

### No broken internal links

- **Rule**: All internal Markdown links and file references must resolve to existing files in the repository
- **Enforcement**: agent
- **Tool**: agent review
- **Scope**: pr

### CHANGELOG updated in every PR

- **Rule**: Every pull request must include at least one change to `CHANGELOG.md`
- **Enforcement**: agent
- **Tool**: agent review
- **Scope**: pr

### README updated in every PR

- **Rule**: Every pull request that adds or changes user-facing features must include corresponding updates to `README.md`
- **Enforcement**: agent
- **Tool**: agent review
- **Scope**: pr

### Directory naming is kebab-case

- **Rule**: All directories must use lowercase kebab-case naming (e.g. `my-skill-name`, not `mySkillName` or `My_Skill`)
- **Enforcement**: agent
- **Tool**: agent review
- **Scope**: pr
